## ADDED Requirements

### Requirement: Agent-owned human terminal output is localized through one presentation boundary

All Neko-owned human-readable output emitted by Agent terminal surfaces SHALL be generated by an explicit command-family Presenter or equivalent terminal presenter using an injected immutable presentation context. This includes Ink and non-Ink command output, startup/status chrome, menus, usage, success text and owned diagnostic wrappers. Built-in Presenters SHALL be statically imported and directly dispatched; this change SHALL NOT introduce a runtime Presenter registry, string-key lookup, fallback Presenter, global all-command semantic-result union, universal command AST or generic Menu AST.

Output ownership SHALL be classified by output channel rather than command family, runtime class or executable mode. Interactive, validation and utility commands MAY each expose both a human projection and a machine projection. Neko-owned human stdout/stderr, including one-shot wrappers, configuration and experiment terminal notices, and Commander help, descriptions, usage and examples, SHALL enter the presentation boundary. Model responses, custom content and external detail SHALL remain semantic values rather than owned messages. Owner bundles SHALL contain only plain text and interpolation placeholders; ANSI/Chalk styling, Ink markup, terminal-width wrapping, indentation and renderer-specific line composition SHALL remain terminal-adapter responsibilities. Presenters SHALL own semantic rows, row ordering and field grouping. Terminal adapters SHALL own physical wrapping, continuation indentation, truncation, available-width behavior and structural glyphs. Different adapters MAY produce different physical line breaks but SHALL preserve the same semantic fields and order. Bundles SHALL NOT contain fixed-width padding, and no global CJK punctuation or spacing post-processor SHALL rewrite translated messages, external text, paths or identifiers.

Hooks, host ports, providers, command-family handlers and runtime/domain services SHALL return small command-family semantic data, `void`, or typed diagnostics rather than final Neko-owned success/error sentences. The router SHALL invoke the canonical Presenter and MAY carry its rendered `output`/`error` in the existing outer `TuiCommandRouterResult`, which remains a terminal projection contract rather than a domain result. `projectCommandResult`, conversation-store projection and the existing TUI message protocol SHALL NOT be redesigned solely to transport semantic command results. The generic status projection contract and pure Presenter SHALL live in a dedicated package-private module inside the existing `packages/neko-agent/packages/cli-tui` package, separate from command routing. It SHALL NOT create a new subpackage or public-index export. `useSlashCommands` SHALL remain the composition adapter. For each `/status` request it SHALL capture each owning Zustand store exactly once and directly supply one readonly semantic snapshot through the injected status provider. Re-reading the same store for separate snapshot fields is prohibited. The package-private status contract and Presenter SHALL NOT import Zustand stores, configuration readers, path APIs or filesystem facilities. The router SHALL invoke the provider and Presenter without reading stores or composing status prose. Cross-store atomicity SHALL NOT be introduced; the snapshot is a best-effort coherent command-time view without locks, versions, subscriptions, caches or synchronization protocols. No Status service, repository or Snapshot Builder SHALL be introduced. A pure projector MAY be extracted only after a second real composition adapter demonstrates duplicate mapping. Readonly SHALL be enforced by TypeScript contracts and construction discipline, not `Object.freeze`, deep cloning, mutation proxies or an immutable-collection framework. Generic status composition SHALL reuse canonical exported domain/runtime read models and SHALL NOT create parallel TUI domain DTOs or carry preformatted Neko-owned `*Summary` prose. When an owning boundary lacks a reusable read model, that boundary SHALL define the canonical type. The Presenter SHALL exclusively own localized labels, status words, human-value formatting, row ordering, punctuation and line breaks. Missing required semantic data, canonical Presenter wiring or message keys SHALL fail visibly rather than produce English fallback, unresolved keys, empty output or a legacy success path.

### Requirement: Shared i18n infrastructure and package-owned bundles are used

The existing `@neko/shared/i18n` entrypoint SHALL provide a small Layer-0 strict translator composition primitive that accepts an already resolved `SupportedLocale`, validates and merges statically supplied owner bundles, reuses shared interpolation semantics and returns an immutable translator. It SHALL NOT create another i18n/localization package, depend on Node or React, perform locale detection or source resolution, mutate locale, access environment/files, dynamically load or discover bundles, use a registry, fall back to English, or emit an unresolved key. Missing selected-locale keys, invalid bundles, namespace collisions and parity violations SHALL fail visibly. Bundle validation and placeholder compilation SHALL occur once during invocation composition; translation calls SHALL NOT rescan every bundle. Terminal composition SHALL create one translator per invocation without a global singleton or mutable translator cache. Existing Webview consumers of the mutable/fallback `I18nService` SHALL retain their current behavior; terminal composition SHALL NOT use `setLocale()` or depend on that fallback chain.

`@neko/agent` SHALL own and colocate flat `agent.command.*` `en`/`zh-cn` bundles, their derived key type and parity tests, reusable across terminal adapters. It SHALL export only that contract through one narrow terminal-message module rather than its root barrel. The existing `cli-tui` package SHALL own and colocate package-private flat `agent.terminal.*` labels, chrome, menu wording, layout wording and wrappers; its bundle SHALL NOT become a general UI catalog. `@neko/cli` SHALL statically import the Agent module and its own bundle and merge exactly those owners. `@neko/agent` SHALL NOT depend on `@neko/cli`. This change SHALL NOT introduce a central repository-wide catalog, filesystem/runtime-glob discovery, dynamic import, plugin bundle contribution, network locale pack, lazy locale chunk or bundle registry. Each owner SHALL define its canonical English bundle as the message-key source of truth and derive its typed key union from that bundle. The terminal key type SHALL be the union of both owner key unions; no duplicated handwritten enum, protobuf key schema, code generation or repository-wide key registry SHALL be introduced.

For each owner, built-in `en` and `zh-cn` bundles SHALL have exact key parity and exact interpolation-placeholder-name parity. Interpolation parameters SHALL remain `Readonly<Record<string, string | number>>`; this change SHALL NOT generate a separate parameter interface for every key. Strict messages SHALL accept only named identifier placeholders such as `{modelId}` and `{count}`. Positional placeholders, property lookup, nesting, conditions, plural expressions, formatter pipes and runtime code SHALL be invalid. `{{` and `}}` SHALL encode literal braces; malformed or unclosed braces SHALL fail bundle validation. Supplied parameter names SHALL exactly match the selected message placeholders: missing, extra or `undefined` parameters SHALL fail visibly. Values SHALL be inserted once without recursive interpolation, translation, trimming or locale normalization, and terminal-safe quoting SHALL remain an explicit caller formatter. Messages SHALL be complete independently translatable semantic units rather than caller-concatenated prefixes, connectors or suffixes, and stable values SHALL enter through placeholders. Multiline output SHALL be composed from atomic semantic row messages plus stable values. Singular/plural distinctions required by English SHALL use explicit parity-checked owner keys selected from semantic count; the translator SHALL NOT infer plurality from rendered text. This change SHALL NOT introduce ICU MessageFormat, Fluent or another plural/message DSL. Only proven-reused terminal layout helpers MAY be shared; no terminal rendering AST SHALL be introduced. Menu Presenters MAY produce the existing `TuiSelectionItem` projection, but handlers SHALL select by stable ID/canonical identity and SHALL NOT parse localized labels.

### Requirement: UI locale and prompt locale resolve coherently once per invocation

Terminal UI and built-in prompt asset selection SHALL use independently configurable preferences with the common vocabulary `auto | en | zh-cn`. Canonical explicit entrypoints SHALL be:

| Preference | CLI | Environment | User TOML |
| --- | --- | --- | --- |
| UI | `--ui-locale` | `NEKO_UI_LOCALE` | `ui_locale` |
| Prompt | `--prompt-locale` | `NEKO_PROMPT_LOCALE` | `prompt_locale` |

A generic `--locale` SHALL NOT be added. The legacy `NEKO_LOCALE` entrypoint SHALL be removed without an alias, warning adapter or behavior that fans one value out to both preferences.

Resolution SHALL use the following precedence:

```text
UI:     CLI → environment → user configuration → detected host locale
Prompt: CLI → environment → user configuration → resolved UI locale
```

Each CLI/environment/config source adapter SHALL preserve absence versus a structurally present raw string and SHALL NOT trim, lowercase, normalize, alias, apply precedence or provide fallback. One validator SHALL strictly validate every present explicit source, including empty and otherwise shadowed values, before selection. Only exact `auto`, `en` and `zh-cn` SHALL be valid explicit values; leading/trailing whitespace, alternate casing, aliases and locale variants SHALL fail visibly.

Host detection SHALL be separate from explicit validation. When no explicit Locale wins, it SHALL follow the operating system's first preferred language. Chinese detected families SHALL normalize to `zh-cn`; an unsupported or unavailable preferred language SHALL resolve to `en`, and detection SHALL NOT scan later preferred languages for a supported alternative. On macOS, an invocation-scoped adapter SHALL read the first `AppleLanguages` entry using fixed `/usr/bin/defaults` arguments without a shell, and that value SHALL take precedence over conflicting POSIX environment or Intl values. On other platforms, process locale sources SHALL use `LC_ALL → LC_MESSAGES → LANGUAGE → LANG → Intl.DateTimeFormat().resolvedOptions().locale`; they MAY remove encoding/modifier syntax, treat `_` and `-` equivalently and use the first `LANGUAGE` token. Detection SHALL run only during bootstrap and SHALL NOT retain a module-level mutable cache, watcher or command-time re-read.

Prompt `auto` or omission SHALL resolve to the final UI locale. A concrete prompt value MAY differ. `auto` SHALL remain a source/configuration mode only; both resolved values SHALL be concrete `SupportedLocale` before any presentation or Agent runtime path is created. Model response language SHALL remain governed by user instruction and conversation context.

Locale preferences SHALL NOT enter merged `UnifiedConfig` because workspace configuration participates in that contract. User raw preferences SHALL be read separately and the resolved concrete `promptLocale: SupportedLocale` SHALL be supplied as invocation runtime input. Terminal/runtime assembly SHALL use the explicit product-level name `promptLocale`; an unambiguous prompt-domain-local context MAY map it once to an internal `locale` field, but optional free-form `locale?: string` SHALL NOT remain the canonical invocation boundary.

The same concrete `promptLocale` SHALL reach all Neko-owned built-in prompt-bearing paths used by the invocation, including system prompt, built-in prompt modules, built-in Skills, capability prompts/catalogs, tool-description projection, validation/recovery, compression, Agent/task creation and AgentSession assembly. Those paths SHALL NOT re-read sources, detect host locale, derive from `uiLocale`, silently default to English or accept legacy `zh`/`zh-CN` aliases on the canonical path. Paths touched by this change SHALL use shared `SupportedLocale`.

SubAgents, task continuations and invocation-owned background Agent workflows SHALL inherit their parent's concrete `promptLocale` without another resolution pass. Resume SHALL use the newly started invocation's resolved prompt locale for new built-in prompt assembly; conversation history SHALL NOT persist an active prompt locale and existing messages SHALL remain unchanged. Custom Skill content, workspace prompts/instructions, user input, history and external MCP/provider/tool/contributor text SHALL remain unchanged and SHALL NOT be automatically translated or subjected to built-in bundle parity.

Terminal bootstrap SHALL follow this order before command exposure: capture every source once → validate all explicit sources → resolve `uiLocale`/`promptLocale` → validate owner bundles → create the strict translator → create the immutable presentation context → expose commands and render Ink. Source readers SHALL not be retained. The final UI locale, prompt locale, translator, formatters and selected built-in prompt assets SHALL remain immutable for the invocation. The command router SHALL receive the context by explicit parameter injection, and the Ink tree SHALL receive that same object through a package-private React Context. The React Context SHALL NOT own locale state, setters, detection, a bundle registry or fallback behavior. Command-time locale re-detection is prohibited.

### Requirement: Diagnostics and human values preserve semantic identity

A terminal diagnostic SHALL contain a stable locale-neutral code, a Neko-owned localized message key/parameters and optional unchanged external detail. Typed diagnostics SHALL represent expected command failures. Programming errors, impossible states and missing canonical Presenter wiring SHALL remain fail-visible and SHALL NOT be converted into user diagnostics. Human bootstrap diagnostics that include raw explicit Locale values SHALL format them through one bounded quoting/escaping helper. Machine failure projections SHALL use existing locale-neutral structured envelopes and SHALL NOT require parsing localized stderr.

Human success and ordinary human output SHALL be written to stdout; expected human diagnostics SHALL be written to stderr. Programming errors and bootstrap or contract failures SHALL remain fail-visible on stderr and terminate with a non-zero exit code. Localization SHALL NOT change output-channel selection, diagnostic codes or exit codes. Commander parse failures SHALL be captured only by a narrow CLI adapter and converted into typed terminal diagnostics; this change SHALL NOT fork Commander or introduce a general CLI framework.

Human-visible counts, dates/times, durations and byte sizes SHALL use small explicit semantic formatters based on `uiLocale`. Absolute date/time formatting SHALL use explicit `Intl.DateTimeFormat` options and the invocation-scoped system time zone captured once during composition; Presenters SHALL NOT re-read or guess host time-zone state. Domain values carrying an explicit offset or time-zone SHALL preserve that meaning. Duration formatting SHALL consume explicit duration semantics rather than date APIs or relative-time prose. Byte formatting SHALL use fixed binary unit tokens `B`, `KiB`, `MiB` and `GiB` with centralized rounding/precision and locale-aware numeric portions. This change SHALL NOT add user time-zone, unit-system or precision configuration, a formatter registry or locale-specific Presenter copies. IDs, ports, versions, enum-like values and serialized data SHALL remain unchanged.

This change SHALL NOT introduce a generic external-contribution localization adapter or universal localized-text DTO. External provider/tool detail SHALL remain unchanged under a localized Neko-owned wrapper, and stable contributor/provider/model/tool identifiers SHALL remain unchanged.

#### Scenario: External failure keeps raw detail

### Requirement: Command syntax and machine contracts remain locale-neutral

Command names, aliases, argument tokens, option IDs, provider/model/tool/artifact identities, diagnostic codes, JSON field names, structured logs, debug automation and evaluation protocols SHALL remain byte-for-byte stable across supported locales. Shell completion scripts, experiment machine data and evaluation report schemas, suite/variant/fact identifiers and assertions SHALL also remain locale-neutral.

Human and machine output SHALL be separate projections. Machine stdout SHALL be exclusive: JSON output, debug JSONL frames, structured logs, evaluation facts/protocols, shell completion scripts and machine-readable experiment data SHALL contain no localized banner, warning, progress or summary prose. Once debug stdio/JSONL protocol mode starts, stdout SHALL contain protocol frames only. Expected machine failures SHALL use the existing structured protocol envelope and stable diagnostic code; no localized JSON/JSONL message field SHALL be added and protocol consumers SHALL NOT parse localized stderr. Shell completion script content SHALL remain byte-stable across UI locales. Experiment terminal progress and final summaries MAY be localized as human projections, but generated JSON reports and Markdown report bodies SHALL remain owned by the evaluation/report domain and outside terminal bundles.

#### Scenario: Command invocation is locale-independent

#### Scenario: Structured output schema is stable

- **THEN** field names, enum values and termination semantics are identical

#### Scenario: Debug protocol stdout is exclusive
- **WHEN** debug stdio or JSONL protocol mode has started
- **THEN** stdout contains only locale-neutral protocol frames and expected failures use the structured diagnostic frame with a stable code

#### Scenario: Completion script remains tooling output

### Requirement: Generic status exposes only the canonical user-config path

The existing generic human `/status` projection SHALL include one localized user-configuration row for file discovery. It SHALL NOT read, parse, validate, summarize or watch Locale configuration and SHALL NOT report stored/effective Locale values, source precedence, shadowing, activation state or file existence.

The generic human-status semantic snapshot SHALL be the readonly composition of canonical owning-domain/runtime read models plus required `userConfigPath: string` data. It SHALL NOT duplicate owning domain types or contain final Neko-owned summary prose. Required contract values SHALL fail visibly when absent. Missing optional capabilities SHALL remain semantic absence and omit their rows; composition SHALL NOT substitute empty strings, `unknown`, `N/A`, hard-coded English or legacy summaries. Displayable unavailable/unknown conditions SHALL be explicit semantic states localized by the Presenter. Terminal composition SHALL call shared `getUserConfigPath()` exactly once per invocation, capture the resolved absolute path and inject the same value into every status snapshot for that invocation.

The existing `cli-tui` package Presenter SHALL localize only the row label and render the exact injected path. It SHALL receive the captured path as snapshot data rather than resolving it itself. It SHALL NOT contract the path to `~`, convert it to relative form, display duplicate variants, translate, case-fold, separator-normalize or reconstruct it. Missing injection SHALL fail visibly. The Presenter and command-time snapshot provider SHALL NOT invoke persistent configuration-file readers, path-resolution APIs or filesystem I/O; reading already-composed canonical store/runtime state remains the composition adapter responsibility. Machine schemas SHALL remain unchanged.

### Requirement: Migration completeness is enforced by focused quality gates

The OpenSpec task list SHALL be the owned-output inventory and migration checklist, tracking output families and sinks rather than duplicating every translation key. This change SHALL NOT create a separate inventory document, localization manifest, runtime output registry or second release checklist. Implementation SHALL proceed in the order shared strict primitive → invocation locale/bootstrap context → owner bundles → model/media/perception first slice → remaining human-output inventory → legacy removal and complete gates. The model/media/perception command family SHALL be the first slice through command-family semantic results and statically dispatched canonical Presenters. First-slice readiness SHALL NOT mark the capability complete. Each command family SHALL migrate as one unit containing its semantic handler result, Presenter, bundles, tests and deletion or poisoning of obsolete prose/formatter/key paths. Unmigrated families MAY remain visibly unmigrated during sequencing, but a migrated family SHALL NOT retain dual successful projections and the new path SHALL NOT wrap legacy English.

Built-in localization SHALL be guarded by owner-derived typed keys, exact key/placeholder parity, strict-translator failure tests, table-driven `en`/`zh-cn` command-family matrices, deterministic formatter tests with fixed locale/time-zone/input, semantic row/order assertions, a small manually reviewed golden set for `/status`, Commander help and the first command family, router/Ink shared-context identity tests, concrete prompt-locale propagation/inheritance/resume tests, human/machine channel and protocol-exclusivity tests, Commander parse-diagnostic projection tests, plain-text bundle tests, legacy-helper/detector/`zh` fallback removal-or-poison tests, Webview `I18nService` compatibility tests, owned-output inventory closure, existing repository checks and focused review-time residual searches. This change SHALL NOT introduce ICU MessageFormat, Fluent, a generic terminal/document AST, a formatter registry, locale-specific Presenter copies, a global CJK post-processor, configurable punctuation/spacing/unit profiles, reverse parsing of rendered English, a dedicated TypeScript AST checker or localization-gate exception framework. Formatter and Presenter tests SHALL NOT require production code to expose otherwise-internal formatting state. Golden output SHALL NOT be created for every message or updated without manual review; Ink width/styling tests SHALL remain adapter tests rather than bundle-parity tests. Silent legacy fallback SHALL NOT be used. Shared slash-command paths SHALL NOT wrap legacy English in a Presenter, detect/translate completed prose, map prose back to message keys or retain dual semantic/string success paths. After migration, package-local `TuiLocale = 'en' | 'zh'`, `detectTuiLocale`, `getTuiLabels`, `formatTuiTemplate`, `formatTuiLabel` and `TUI_LABELS` SHALL be removed together with legacy `NEKO_LOCALE` and the legacy module-level macOS locale probe/cache; only the canonical invocation-scoped system-locale adapter SHALL remain. No `zh` compatibility alias or wrapper SHALL remain; terminal code SHALL use shared `SupportedLocale` with `zh-cn`. Internal terminal message-key renames SHALL cut over atomically across the canonical English bundle, `zh-cn` bundle, Presenter calls and tests. Deprecated-key aliases, old-to-new maps, dual keys and missing-key fallback SHALL NOT remain; focused migration tests MAY poison removed keys.

This change SHALL NOT introduce a terminal-localization feature flag, staged/percentage rollout, experiment cohort, remote kill switch, legacy locale mode or fallback to the old English runtime. Invalid canonical bootstrap SHALL fail visibly. It SHALL NOT add localization telemetry or analytics for user locale, message-key use, fallback frequency or command language; existing local logging MAY report an explicit bootstrap diagnostic without a localization event schema or pipeline.

Acceptance SHALL have three layers: focused `@neko/shared/i18n`, `@neko/agent` and `@neko/cli` tests including first-slice matrices; impact-selected repository type/test/legacy-debt/unused gates; and focused Agent evaluation only when implementation changes prompt-locale propagation, built-in prompt/Skill/capability/tool-description, AgentSession/SubAgent, validation/recovery or TUI Agent event projection. A key-free harness self-test SHALL NOT be represented as real Agent behavior evidence, and no localization-specific CI or release service SHALL be added.

Documentation SHALL record stable contracts rather than migration logs, command output, timelines or completion diaries. OpenSpec SHALL own active design/tasks; implementation completion SHALL update existing Agent/CLI package or domain architecture documentation only where a long-lived contract or user-facing behavior changed. No separate decision record SHALL be added. README or paired-language documentation SHALL change only when its semantics are affected.

Capability Complete and archival SHALL use one checklist and require every task/inventory family closed, bundle/key/placeholder gates passing, canonical human output routed through Presenters, machine/protocol output locale-neutral, touched built-in prompt paths receiving one concrete prompt locale, obsolete detectors/aliases/environment entrypoints/formatters/keys/dual success paths removed or poisoned, focused/repository/required evaluation gates passing, and verification commands/evidence/residual risk recorded. This change SHALL NOT add a readiness service, runtime localization status, maturity score, percentage-completion API or second release checklist.
