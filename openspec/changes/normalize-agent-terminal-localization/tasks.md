## 2. Locale and Bundle Composition

- [ ] 2.1 Add a small Layer-0 `createStrictTranslator`-style primitive to the existing `@neko/shared/i18n` entrypoint. It accepts only resolved `SupportedLocale`, statically supplied bundles and exact string/number parameters; validates bundle/key/placeholder parity, named placeholder syntax, `{{`/`}}` brace escapes and exact runtime parameter sets once during translator construction; and fails visibly for missing/extra/undefined parameters, invalid bundles, collisions and missing keys without English/key fallback. Keep it free of Node, React, environment, filesystem, discovery, registry and global-singleton concerns. Preserve existing Webview `I18nService` mutation/fallback behavior and do not use `setLocale()` in terminal composition.
- [ ] 2.2 Colocate flat `agent.command.*` `en`/`zh-cn` bundles, key type and parity tests in `@neko/agent` and expose them through one narrow terminal-message module rather than the root barrel; colocate package-private `agent.terminal.*` bundles in `@neko/cli`. Statically import both into CLI composition without reverse dependency, filesystem/glob discovery, dynamic import, registry, plugin contribution, locale pack or lazy locale chunk. Implement complete independently translatable semantic messages with stable values injected through placeholders. Derive each owner key union from its canonical English bundle, compose the two unions for terminal translation and enforce exact `en`/`zh-cn` key plus placeholder-name parity using `Readonly<Record<string, string | number>>` parameters. Represent required English singular/plural distinctions with explicit parity-checked keys selected by the Presenter; do not add handwritten key enums, codegen, protobuf schemas, a central catalog, per-key parameter interfaces, ICU MessageFormat, Fluent or another plural/message DSL.
- [ ] 2.3 Implement paired canonical sources `--ui-locale` / `NEKO_UI_LOCALE` / `ui_locale` and `--prompt-locale` / `NEKO_PROMPT_LOCALE` / `prompt_locale` with UI CLI → environment → user → host and Prompt CLI → environment → user → resolved UI precedence. Do not add generic `--locale`; delete `NEKO_LOCALE` without alias, warning adapter or UI/prompt fan-out.
- [ ] 2.4 Make source adapters preserve absent versus present raw input without trim/lowercase/normalization/precedence/fallback, then validate every present explicit source centrally and reject workspace `ui_locale`/`prompt_locale`; cover empty, leading/trailing whitespace, alternate casing, unsupported alias/variant and shadowed-invalid cases. Implement host-only normalization using `LC_ALL → LC_MESSAGES → LANGUAGE → LANG → Intl`, including encoding/modifier removal, first `LANGUAGE` token, Chinese-family mapping, `C`/`POSIX`, and non-Chinese default `en`; remove macOS `defaults` probing and module-level locale caching.
- [ ] 2.5 Enforce bootstrap order: capture all source values once → validate all explicit sources → resolve UI/prompt locales → statically compose and validate owner bundles/placeholders once → create one strict translator → create one immutable presentation context → expose commands/render Ink. Discard source readers after composition and prove command, React and Agent runtime paths do not re-read environment/config or detect locale. Inject that same object explicitly into the router and through a package-private transport-only React Context into Ink; keep direct user-config edits restart-only and omit locale state/setters/detection/registry from React plus all Locale management commands, mutation DTOs and file watchers.
- [ ] 2.6 Keep Locale preferences outside merged `UnifiedConfig`; define canonical invocation/runtime `promptLocale: SupportedLocale`, resolve `auto` before runtime construction and map it once into any unambiguous prompt-domain-local `locale` field. Migrate touched built-in prompt/Skill/capability/tool-description/validation/compression/AgentSession paths away from optional free-form strings, legacy `zh`/`zh-CN`, local normalization and `locale ?? 'en'`.
- [ ] 2.7 Propagate one concrete `promptLocale` through SubAgents, task continuations and invocation-owned background Agent workflows; make resume use the new invocation value without persisting active Locale or rewriting history, and keep custom Skill/workspace/user/history/external text outside automatic translation and built-in bundle parity.
