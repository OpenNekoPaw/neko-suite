## ADDED Requirements

### Requirement: Canvas AI actions are separate from foreground Agent handoff

Canvas Shot/Scene AI buttons SHALL use typed Canvas creative action requests instead of the foreground `Send to Agent` context handoff.

#### Scenario: Optimize prompt button invokes Canvas creative action
- **WHEN** the user activates the optimize prompt button from the Shot UI
- **THEN** Canvas MUST send a typed creative action request for the relevant prompt target
- **AND** it MUST NOT send the request through `sendToAgent` or `neko.agent.sendContext`

#### Scenario: Send to Agent remains foreground handoff
- **WHEN** the user activates `Send to Agent`
- **THEN** Canvas MUST continue sending the selected Canvas context to the foreground Agent conversation
- **AND** it MUST NOT create a candidate result or background creative run as part of that handoff

### Requirement: Canvas AI actions declare explicit fill targets

Every Canvas creative AI action SHALL declare the candidate target and final mutating target before Agent work starts.

#### Scenario: Missing fill target blocks action
- **WHEN** a Canvas creative AI action cannot resolve a candidate target or final target for the selected shot, scene, field, or media slot
- **THEN** Canvas MUST return a visible diagnostic before invoking Agent
- **AND** Agent MUST NOT infer the target from foreground selection, current Webview state, or natural language

#### Scenario: Prompt optimization declares prompt document target
- **WHEN** Canvas invokes image or video prompt optimization
- **THEN** the request MUST identify the prompt document field that will receive the candidate
- **AND** promotion MUST identify the same final prompt document field unless the user explicitly changes target

### Requirement: AI results are candidate-first

Canvas creative AI results SHALL be applied as candidates before they can mutate formal shot or scene content.

#### Scenario: Generated image produces candidate
- **WHEN** Agent returns a generated image result for a Canvas shot
- **THEN** Canvas MUST apply it to a candidate target with stable resource identity
- **AND** Canvas MUST NOT overwrite the formal image result slot until promotion succeeds

#### Scenario: Optimized prompt produces candidate
- **WHEN** Agent returns an optimized image or video prompt
- **THEN** Canvas MUST store or project it as a candidate prompt result
- **AND** Canvas MUST NOT replace the formal prompt document before user acceptance or judge approval

### Requirement: Candidate promotion requires acceptance or judge pass

Canvas SHALL promote a candidate to the mutating target only after explicit user acceptance or a successful judge workItem.

#### Scenario: User accepts candidate
- **WHEN** the user accepts a candidate generated by a Canvas AI action
- **THEN** Canvas MUST re-check the target revision and apply the candidate to the formal target if the revision still matches
- **AND** Canvas MUST return a stale-target diagnostic instead of overwriting if the target changed

#### Scenario: Judge rejects candidate
- **WHEN** the judge workItem evaluates a candidate as failing quality requirements
- **THEN** Canvas MUST keep the candidate out of the formal target
- **AND** the candidate state MUST remain inspectable with judge diagnostics

#### Scenario: Judge passes candidate with auto-promotion
- **WHEN** a candidate passes judge evaluation and the action explicitly allows auto-promotion
- **THEN** Canvas MUST re-check the target revision before mutating the formal target
- **AND** Canvas MUST record the promotion provenance and judge result

### Requirement: Video prompt document is the sole new video prompt authority

New Canvas AI action flows SHALL use `videoPromptDocument` as the prompt authority for video, voice, dialogue, sound, movement, camera, and screen action content.

#### Scenario: Video generation reads video prompt
- **WHEN** Canvas invokes video generation or video editing
- **THEN** the action MUST include a `videoPromptDocument` reference
- **AND** it MUST NOT depend on a separate `voicePromptDocument` as an input authority

#### Scenario: Editing video prompt with voice content
- **WHEN** the user edits dialogue, voice-over, or sound instructions in the Shot prompt UI
- **THEN** Canvas MUST write that content into `videoPromptDocument`
- **AND** it MUST NOT create a new `voicePromptDocument` for the new AI action path

### Requirement: Canvas preflight validates creative parameters

Canvas SHALL validate creative parameters and model capability requirements before invoking Agent.

#### Scenario: Image edit lacks source image
- **WHEN** the user invokes image editing without a source image or reference image
- **THEN** Canvas MUST show a parameter diagnostic
- **AND** it MUST NOT start an Agent run

#### Scenario: Video generation lacks prompt
- **WHEN** the user invokes video generation without a `videoPromptDocument`
- **THEN** Canvas MUST show a prompt-required diagnostic
- **AND** it MUST NOT start an Agent run

#### Scenario: Unsupported advanced parameter
- **WHEN** shot or scene configuration includes a creative parameter unsupported by the selected model capability projection
- **THEN** Canvas MUST show the unsupported parameter diagnostic before execution
- **AND** it MUST NOT silently drop the parameter and report success

### Requirement: Canvas displays aggregate creative run progress

Canvas SHALL display aggregate progress for creative AI actions while Agent remains responsible for individual workItem progress.

#### Scenario: Batch action starts
- **WHEN** a Canvas AI action creates multiple workItems
- **THEN** Canvas MUST be able to display total, completed, failed, running, and queued counts for the run
- **AND** Canvas MUST NOT infer those counts from Webview-local timers or provider-specific responses

#### Scenario: WorkItem progresses
- **WHEN** Agent updates one image, audio, video, prompt, or judge workItem
- **THEN** Canvas MAY update aggregate progress from the Agent snapshot
- **AND** individual progress details MUST remain sourced from Agent workItem state

### Requirement: Migrated Canvas AI buttons do not use legacy generation success paths

Canvas AI buttons migrated by this change SHALL not succeed through legacy foreground or data URL paths.

#### Scenario: Legacy generate command is poisoned
- **WHEN** tests poison `neko.agent.generateForNode` so it throws or returns a diagnostic if called by a migrated button
- **THEN** the migrated Canvas AI button flow MUST still succeed through the creative run and candidate apply path
- **AND** the test MUST fail if the legacy command participates in success

#### Scenario: Generation progress data URL is ignored for migrated action
- **WHEN** a migrated Canvas AI action completes
- **THEN** success MUST be based on candidate ResourceRef or structured candidate apply
- **AND** it MUST NOT depend on `generationProgress` with a `dataUrl`
