### 1.2 neko-preview/webview (16个)

**分析结果**: 这些文件实际上**被使用**，但 knip 检测为未使用

**原因**:
- `audio/main.tsx` 和 `video/main.tsx` 是独立的 webview 入口
- 通过 HTML 文件引用，不是通过 TypeScript import
- knip 无法检测到 HTML → TS 的依赖关系

**处理建议**: 在 knip.config.ts 中添加 entry 声明

```typescript
'packages/neko-preview/packages/webview': {
  entry: [
    'src/audio/main.tsx',
    'src/video/main.tsx',
  ],
}
```

### 1.3 neko-tools/webview (15个)

**分析结果**: 同 neko-preview，实际被使用

**原因**: `mediaDiff.tsx` 是独立 webview 入口

**处理建议**: 添加 entry 声明

```typescript
'packages/neko-tools/packages/webview': {
  entry: ['src/mediaDiff.tsx'],
}
```

### 1.4 neko-agent/webview (2个)

**分析结果**:
- `components/ChatView/InputArea/index.ts` - barrel 导出文件，实际被使用
- `config/index.ts` - 配置文件，实际被使用

**处理建议**: 添加 entry 或 ignore

## 二、未使用依赖分析 (21个)

### 2.1 根依赖 (2个) - ❌ 移除

```json

"d3-shape": "^3.2.0"
```

**分析结果**:
- 仅在 `neko-agent/webview/vite.config.ts` 的 `dedupe` 配置中引用

## 六、长期建议

### 6.1 导出风格规范

**统一使用命名导出**:

```typescript
// ✅ 推荐
export function MyComponent() { ... }
export class MyService { ... }
export const myApi = { ... };

// ❌ 避免
export default MyComponent;
```

**例外情况**:
- 配置文件 (vite.config.ts, knip.config.ts)
- 动态路由组件 (如果使用 Next.js)

### 6.2 依赖管理规范

**原则**:
1. 依赖声明在使用它的最近包中
2. 父包不声明子包的依赖
3. peer dependencies 显式声明（即使间接使用）

### 6.3 Knip 集成

**建议**:
1. 将 `pnpm check:unused` 集成到 CI/CD
2. 每月运行一次完整分析
3. 新功能开发时及时更新 ignore 规则
