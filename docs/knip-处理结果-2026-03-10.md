## 六、经验总结

### 6.1 Knip 使用技巧

1. **区分误报和真实问题**: 并非所有 knip 报告的问题都需要删除代码
2. **理解工具限制**: knip 无法检测 HTML → TS 的依赖关系
3. **合理使用 ignore**: 对于待实现功能，使用 ignore 而非删除代码
4. **peer dependencies**: 间接依赖需要显式声明在 ignoreDependencies

### 6.2 导出风格最佳实践

**推荐**: 统一使用命名导出
```typescript
// ✅ 推荐
export function MyComponent() { ... }
export class MyService { ... }
export const myApi = { ... };
```

**避免**: 默认导出（除配置文件外）
```typescript
// ❌ 避免
export default MyComponent;
```

**例外**: 配置文件可以使用默认导出
```typescript
// ✅ 配置文件例外
export default defineConfig({ ... });
```

### 6.3 Monorepo 依赖管理

**原则**:
1. 依赖声明在使用它的最近包中
2. 父包不声明子包的依赖
3. peer dependencies 显式声明（即使间接使用）
4. 定期审查依赖树，清理冗余依赖
