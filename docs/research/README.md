# 调研分析

`docs/research/` 用于保存竞品分析、市场扫描、技术 spike、UX 观察和方案比较。调研可以影响架构和路线图，但它本身不是架构事实来源。

## 子目录

| 目录 | 用途 |
|------|------|
| `competitors/` | 竞品、赛道和能力对标 |
| `technical-spikes/` | 技术验证和方案比较 |
| `market/` | 市场、生态和分发分析 |
| `ux/` | 交互、创作流程和用户体验观察 |

未产生正文前不必创建所有子目录。

## 写作要求

每份调研文档应标注：

- 日期或调研周期；
- 信息来源；
- 结论可信度和不确定性；
- 对 Neko Suite 的影响；
- 是否需要转化为 `docs/architecture/`、`docs/domains/`、`ROADMAP_CN.md` 或 OpenSpec change。

竞品分析建议按赛道组织，而不是按单个公司或产品堆文件。
