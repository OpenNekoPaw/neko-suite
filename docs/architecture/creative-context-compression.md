# 创作领域上下文压缩策略

> ADR Status: Proposed  
> Date: 2026-03-31  
> Scope: neko-agent context compression for creative workflows

---

## 1. 背景

neko-agent 当前的 `ConversationCompressor` 采用**滑动窗口 + 摘要**策略，按时间切割对话：保留最近 N 轮完整消息，旧轮次整体摘要或丢弃。这种策略适合通用编码场景，但 neko-suite 作为图文音视频创作工具，创作对话有本质不同的信息结构。

本文档分析一种面向编码场景的 7 级优先级压缩策略，评估其在创作领域的适用性，并提出适配方案。

---

## 2. 编码场景 7 级优先级压缩策略

| 优先级 | 信息类型 | 保留策略 |
|--------|---------|---------|
| 1 | 用户所有消息 | 100% 完整保留，绝不压缩 |
| 2 | 关键决策 | 架构选择、技术选型、方案决策等 |
| 3 | 代码变更 | 文件编辑、创建、删除的内容和原因 |
| 4 | 工具调用链 | 工具调用的目的、参数、关键结果 |
| 5 | 技术上下文 | 重要概念、框架、API 使用方式 |
| 6 | 计划与目标 | 项目目标、待办列表、里程碑 |
| 7 | 最近 N 轮对话 | 最近 5 轮完整保留（可配置） |

### 压缩 Prompt 要求

1. 识别关键决策、技术概念和代码模式
2. 枚举所有检查、修改、创建的文件，包含代码片段和重要性说明
3. 保留所有用户消息，理解用户反馈和意图变化
4. 总结继续工作所需的上下文、决策和状态

## 3. 当前实现 vs 编码场景策略的差异

### 当前 ConversationCompressor 实现概述

```
系统提示词 (Turn 0) → 永不压缩
最近 10 轮           → 完整保留（仅压缩 tool result 字段）
更老轮次             → 整体摘要（2000 token）或直接丢弃
```

核心配置默认值：
- `recentTurns: 10`
- `olderTurnsStrategy: 'summary'`
- `olderTurnsSummaryMaxTokens: 2000`
- `tokenThreshold: 80000`
- `turnThreshold: 20`

### 逐项对比

| 优先级 | 编码策略 | 当前实现 | 差距 |
|--------|---------|---------|------|
| **1. 用户消息** | 100% 保留 | 仅保留最近 10 轮内的用户消息；旧轮次用户消息被摘要吞没 | **严重缺失** — 旧用户消息丢失原文 |
| **2. 关键决策** | 单独提取保留 | 无识别机制，决策信息混在轮次里，超出窗口即丢失 | **完全缺失** — 无语义分类能力 |
| **3. 代码变更** | 枚举文件 + 代码片段 | tool result 保留 `status/summary/error/result`，`rawData` 被丢弃；无文件变更追踪 | **大部分缺失** |
| **4. 工具调用链** | 目的 + 参数 + 结果 | tool call 的 function name + parameters 在窗口内保留；旧轮次完全丢失 | **部分实现** — 仅窗口内 |
| **5. 技术上下文** | 概念 / 框架 / API | 无提取机制 | **完全缺失** |
| **6. 计划与目标** | 目标 / 待办 / 里程碑 | 无识别机制 | **完全缺失** |
| **7. 最近 N 轮** | 最近 5 轮（可配置） | 最近 10 轮（可配置） | ✅ 已实现 |

### 核心差距总结

1. **无语义分类，仅按时间切割** — 当前实现是纯滑动窗口，不区分消息类型，无法按优先级保留
2. **用户消息未获最高保护** — 超出窗口的用户消息被摘要替换，原始意图丢失
3. **摘要质量不可控** — LLM Summarizer 使用通用 prompt，无结构化压缩指令
4. **缺少渐进式降级** — 二元切割（窗口内完整 / 窗口外摘要），无中间状态

## 4. 创作领域适配分析

### 4.1 适用的部分

| 优先级 | 策略 | 创作场景适用性 |
|--------|------|--------------|
| 1. 用户消息 100% 保留 | **完全适用** | 创作意图全靠用户表达，"更暖一点"、"节奏再快些" 丢失任何一条都导致理解断裂 |
| 6. 计划与目标 | **适用** | 创作项目同样有阶段目标（"先出分镜 → 配音 → 合成"） |
| 7. 最近 N 轮保留 | **适用** | 创作迭代高度依赖最近上下文 |

### 4.2 需重新定义的部分

#### 优先级 2：关键决策 → 创作方向决策

```
软件工程决策:                    创作领域决策:
├─ 用 Redis 还是 Memcached       ├─ 整体风格: 赛博朋克 / 水墨风 / 扁平
├─ REST 还是 GraphQL              ├─ 色彩基调: 暖色为主，冷色点缀
├─ 微服务还是单体                 ├─ 叙事结构: 三幕式 / 非线性
└─ 状态管理方案                   ├─ 音乐风格: Lo-fi / 交响 / 电子
                                  ├─ 画面构图: 对称 / 三分法 / 引导线
                                  └─ 角色设定: 性格、外貌、声线确定
```

这些决策一旦确立，后续所有迭代都在此框架内。丢失风格决策 = 后续生成结果风格漂移。

#### 优先级 3：代码变更 → 资产状态变更

```
代码变更:                        资产状态变更:
├─ 文件编辑/创建/删除            ├─ 图层操作: 添加/合并/删除/重排序
├─ 代码片段                      ├─ 时间线: 片段裁剪/移动/转场设置
├─ 重要性说明                    ├─ 生成历史: prompt → 结果 → 用户评价
                                 ├─ 参数快照: 模型/采样器/CFG/种子
                                 └─ 版本节点: "这版OK" / "回退到第3版"
```

关键差异：创作资产有**版本演进链**——用户说"回到之前那个感觉"时，需要知道"之前"是哪个版本、用了什么参数。

#### 优先级 4：工具调用链 → 生成管线记录

```
工具调用链:                      生成管线记录:
├─ 工具名 + 参数 + 结果         ├─ 模型 + prompt + 负面 prompt + 参数
├─ 链式调用关系                  ├─ 后处理链: 放大 → 修脸 → 调色 → 锐化
└─ 关键结果                      ├─ 用户对结果的评价: "太暗了" / "完美"
                                 └─ 迭代关系: 在第N版基础上做了什么调整
```

创作场景中，**用户对中间结果的评价**和参数同等重要。

#### 优先级 5：技术上下文 → 审美上下文

```
技术上下文:                      审美上下文:
├─ 框架、API 用法               ├─ 参考图/参考视频的描述
├─ 概念解释                      ├─ 用户审美偏好积累
└─ 模式约定                      ├─ 领域术语: 景深/色温/BPM/关键帧
                                 └─ 约束条件: 分辨率/时长/格式/平台规范
```

### 4.3 编码策略完全缺失的创作关键维度

| 缺失维度 | 重要性 | 说明 |
|----------|--------|------|
| **迭代演进链** | 极高 | 创作是渐进式的："第1版太冷 → 加暖色 → 过饱和 → 降低20% → OK"。丢失任何一环，后续 "再调一下" 失去基准 |
| **多模态引用** | 极高 | "像刚才那张图的构图，配上第二段的音乐节奏"——跨模态引用是创作对话常态，纯文本策略无法处理 |
| **审美偏好累积** | 高 | 用户在多轮交互中隐式表达偏好（接受暖色、拒绝高对比），需持续追踪 |
| **空间/时间坐标** | 高 | "左上角的元素"、"1:30 处的转场"、"第三图层"——位置信息是创作指令的核心组成 |
| **版本锚点** | 中 | 用户标记的"这版不错"是回退和分支的基准点，必须显式保留 |

## 5. 创作领域压缩策略设计

### 5.1 重构后的 7 级优先级

```
优先级  信息类型              保留策略
─────────────────────────────────────────────────────
  1     用户消息              100% 保留原文（不进入摘要流程）
  2     创作方向决策          风格/基调/角色设定/叙事结构 完整保留
  3     版本锚点 + 评价       用户标记的满意版本 + 对每版的评价
  4     迭代演进链            prompt → 参数 → 结果摘要 → 用户反馈 的链式记录
  5     资产状态              当前图层/时间线/画布的结构化快照
  6     审美偏好              累积的接受/拒绝信号（可压缩为偏好向量）
  7     最近 N 轮             最近 5 轮完整保留（可配置）
```

### 5.2 与编码策略的核心区别

1. **引入"版本锚点"概念** — 创作不是线性推进，需要支持回退和分支
2. **迭代链 > 单次调用** — 编码关注单次工具调用结果，创作关注多次迭代的演进关系
3. **评价即数据** — 用户对中间结果的主观评价（"太暗"/"不够动感"）是压缩后必须保留的一等信息
4. **结构化快照替代代码 diff** — 用资产状态快照（图层树、时间线结构）替代代码变更记录

### 5.3 创作领域压缩 Prompt 要求

```
1. 识别创作方向决策（风格、基调、角色设定）和迭代模式
2. 枚举所有创作资产操作（图层/时间线变更 + 生成参数快照）
3. 保留所有用户消息原文，理解用户审美反馈和意图变化
4. 总结继续创作所需的上下文：当前版本状态、已确定的风格、待解决问题
```

### 5.4 实现方向

#### 扩展点利用

当前系统提供三个扩展点，无需大幅重构：

1. **`ISummarizer` 接口** — 注入创作领域专用摘要器，替换通用 prompt
2. **`ConversationCompressorConfig`** — 运行时调整 `keepFields`/`discardFields`/`recentTurns`
3. **`ExecutorHooks` 组合** — 在 `beforeThink` 前增加消息分类预处理

#### 新增组件

```
IMessageClassifier（消息分类器）
├─ 规则引擎: 关键词 + 角色 + 工具类型 → CreativeInfoType
├─ 可配置关键词列表
└─ 输出: MessageClassification[]

CreativeSummarizer（创作摘要器）implements ISummarizer
├─ 先分类再摘要（分类器输出驱动）
├─ P1 用户消息: 直接保留原文
├─ P2-P6: 按类型分组，各组独立 token 预算
├─ P7: 极简摘要或丢弃
└─ 结构化输出（决策/锚点/偏好分段）
```

#### 压缩流程改造

```
现有流程:
  旧轮次 → 整体摘要(2000 token) 或 丢弃

改造后:
  旧轮次 → 分类(IMessageClassifier)
         → P1 用户消息直接保留
         → P2 创作决策 → 专项摘要(500 token)
         → P3 版本锚点 → 专项摘要(300 token)
         → P4 迭代链   → 专项摘要(600 token)
         → P5 资产状态 → 专项摘要(300 token)
         → P6 审美偏好 → 专项摘要(300 token)
         → P7 其他     → 丢弃
         总预算: 2000 token（与现有一致）
```

## 7. 对比总结

| 维度 | 编码场景策略 | 创作领域策略 |
|------|------------|------------|
| 分类依据 | 代码/工具/技术 | 审美/资产/迭代 |
| 核心保留 | 架构决策 + 代码变更 | 风格决策 + 版本锚点 |
| 时间模型 | 线性推进 | 分支回退 |
| 评价角色 | 次要（测试通过/失败） | 一等信息（审美判断） |
| 多模态 | 无（纯文本/代码） | 必须（图/音/视频引用） |
| 参数追踪 | 配置文件 diff | 生成参数快照链 |
