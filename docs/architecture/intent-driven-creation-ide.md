## 1. 核心哲学

**创作工具的 Agent 不是代码 Agent 的平移，是范式级重构。**

### 三条根本判断

1. **意图驱动是未来主流**（类比摄影民主化），但技术驱动作为专业后端永不消失
2. **意图天然多模态**（图像/视频/音频/手势/演示），单文本驱动是创作工具的死胡同
3. **创作工具本身就是最好的意图传感器**——这是对抗 Runway/Midjourney 的结构性护城河

## 2. 四层整合架构

```
┌──────────────────────────────────────────────────┐
│ L4 意图层（What 用户想要）                        │
│   意图画布 / Proposal / Skill 场景包             │
│   多模态输入：文本 + 图 + 音 + 草图 + 演示        │
└──────────────┬───────────────────────────────────┘
               │ 双向编译（意图 ↔ 技术）
               ▼
┌──────────────────────────────────────────────────┐
│ L3 Agent 编排层（AI 作为编译器）                 │
│   单一通用 Agent + Skills 场景包 + SDD 4 阶段    │
│   强模型驱动（Claude Opus/Sonnet）               │
│   ApprovalEngine + EventBus + AutoHeal           │
└──────────────┬───────────────────────────────────┘
               │ CapabilityProvider 协议
               ▼
┌──────────────────────────────────────────────────┐
│ L2 创作工具层（How 精确执行 + 意图传感）         │
│   cut / canvas / model / sketch / puppet / story │
│   每个子包 = 执行器 + 传感器 + 协作者            │
└──────────────┬───────────────────────────────────┘
               │ 统一 Rust 引擎
               ▼
┌──────────────────────────────────────────────────┐
│ L1 引擎与基础设施层                              │
│   Rust 引擎（FFmpeg/wgpu/ONNX/设备 I/O）         │
│   @neko/shared（PathResolver/i18n/Theme）        │
│   媒体库（角色/风格/世界观/LoRA）                │
└──────────────────────────────────────────────────┘
```

**职责正交**：
- L4 捕获意图（用户语言）
- L3 编译意图为技术方案（AI 推理）
- L2 执行技术方案 + 反馈意图信号（工具操作）
- L1 提供统一计算与资产底座

## 3. 意图的双向流动（核心机制）

```
用户意图表达 ──► L4 意图画布（多模态捕获）
                      ↓
                L3 Agent 编译为 ExecutionPlan
                      ↓
                L2 创作工具精确执行
                      ↓
用户直接操作 ──► 操作流反向编译为意图信号
                      ↓
                L3 Agent 更新意图理解
                      ↓
                主动建议/变体/扩展返回用户
```

**关键创新**：**工具操作即意图输入**，而非仅执行输出。

### 3.1 双向编译的本质

| 方向 | 编译过程 | 失败语义 |
|------|---------|---------|
| 意图 → 技术 | Agent 把 Proposal 编译为 ExecutionPlan | 方向错（用户介入）|
| 技术 → 意图 | Agent 观察操作流反推意图 | 模式不清（被动等待）|

**两种编译都需要 LLM 推理，但置信度处理不同**：
- 正向编译：用户审批后执行（高确定性）
- 反向编译：仅作为意图信号累积（低确定性，不直接行动）

## 5. 多模态意图捕获

### 5.1 六种意图通道

| 通道 | 示例 | 作用 |
|------|------|------|
| **文本** | "Z 世代 TikTok 风格" | 高层概念/约束声明 |
| **图像** | 参考图/mood board/草图 | 视觉风格/构图 |
| **视频** | 参考片段/动态示范 | 运动/节奏/转场 |
| **音频** | 哼唱/参考 BGM/语气 | 旋律/氛围/配乐 |
| **手势/绘制** | 画草图/标注/圈选 | 空间意图/修改点 |
| **演示操作** | 用户在 Timeline 上示范一段 | 行为意图（"按这样做"）|

**关键洞察**：创作者**本能地混用**这六种通道表达意图，文本只是其中一种。

### 5.2 意图画布（替代聊天框成主入口）

**为什么聊天框不够**：
- 聊天框隐含"文本优先"的偏见
- 创作意图天然多模态，被压缩成文本损失 80% 信息

**意图画布特征**：
- 可同时拖入图/视频/音频/草图统一表达意图
- 多模态平等，文本只是其中一种
- 参考媒体语义解构（"你喜欢这图的构图、色调、主体还是氛围？"）
- 参考：Figma FigJam 的白板 vs Slack 的聊天

### 5.3 参考媒体的语义解构

不能把整张图塞给 AI 说"照这个做"，应反问：

```
用户：拖入参考图 + "做类似的"
   ↓
Agent：你喜欢这图的：
   ☐ 构图（三分法/对称/中心）
   ☐ 色调（暖/冷/对比度）
   ☐ 主体（人物/物体/场景）
   ☐ 氛围（情绪/时代感/质感）
   ☐ 全部要素
   ↓
用户精炼意图，意图分辨率从 60% → 90%
```

## 6. 创作工具作为意图传感器

### 6.1 为什么工具操作是最高分辨率的意图

| 意图表达方式 | 信息密度 | 精确度 | 学习成本 |
|------------|---------|--------|---------|
| 文本描述 | 低 | 40% | 0 |
| 参考图 | 中 | 60% | 低 |
| 草图 | 中高 | 70% | 中 |
| **工具内操作** | **极高** | **95%** | **0（创作者本就会）**|

**关键洞察**：创作者在 Timeline 上剪一刀、在 Canvas 上调个布局、在 Model 里动个骨骼——**每个操作都是完整、精确、无歧义的意图表达**。

### 6.2 工具操作优于其他意图输入的四大理由

1. **操作本身就是意图的"原生语言"** —— 不需要翻译、不会歧义、不丢信息
2. **创作者"用工具思考"** —— 强迫先描述意图再执行 = 打断创作流
3. **操作流露未被意识化的意图** —— 文本只能捕获意识层意图，操作能捕获肌肉记忆层意图
4. **工具操作自带上下文** —— 操作 = 意图 + 上下文 + 精确度三合一

### 6.3 工具传感器的四层能力

```
Layer 1：操作事件捕获（基础）
  统一 OperationEvent schema，跨子包语义一致

Layer 2：操作 → 意图反编译
  模式识别：连续 3 次同参数调整 = 关键意图
  反复撤销重做 = 用户在犹豫，可建议变体

Layer 3：意图累积与画像
  跨会话累积形成个人美学画像
  10 次都偏短镜头 = 偏快节奏

Layer 4：意图主动反馈
  Agent 观察后主动介入
  从"响应式对话"升级到"共感式协作"
```

### 6.4 工具即传感器的三种形态

| 形态 | 介入度 | 适用场景 |
|------|-------|---------|
| **被动观察式** | 最低 | Agent 在侧边观察，定期摘要，不打扰 |
| **主动建议式** | 中等 | 观察到模式后主动弹出建议 |
| **协同创作式** | 深度 | 用户做一半，Agent 自动完成剩下 |

## 7. 双范式共存（意图 ↔ 技术）

**不是"意图取代技术"，而是"意图默认 + 技术按需下探"**：

```
新手路径：意图层对话 → AI 编译 → 产出
  ↓ 用户可下探到任何技术层精调
专家路径：直接技术层操作 → Agent 反向理解意图 → 建议增强
```

### 7.1 关键设计约束

- **意图层不能锁死技术层**（必须可展开 ExecutionPlan 编辑）
- **技术工具不能退化为 Agent 附庸**（保持独立可用）
- 两层之间必须有**双向翻译桥**（意图→技术编译 + 技术→意图反编译）

### 7.2 适用场景对照

| 场景 | 推荐范式 | 理由 |
|------|---------|------|
| 创作者想快速产出社交视频 | 意图驱动 | 技术细节是干扰 |
| 专业剪辑师做精细调色 | 技术驱动 | 精确控制不可让渡 |
| 新手想学创作 | 意图驱动起步 + 逐步下探技术 | 降低门槛 |
| 工程化批处理 | 技术驱动 + Preset | 可重复/可审查 |
| 风格探索与迭代 | 意图驱动 + Fork | AI 生成变体效率高 |

## 8. Skill 作为意图场景包

Skill 是**意图驱动的核心分发单元**，一个文件打包完整创作场景：

```yaml
---
name: cut-tiktok-creator
description: What + When（AutoMode 触发依据）
requiredSubpackages: [neko-cut, neko-audio]
allowedTools: [cut.trim, cut.export-mp4]
referencedAssets: [asset://styles/cinematic]
compliance: { framework: SOC2, auditRequired: true }
---

# 人格正文即 system prompt
## 工作流程
先校准风格，再拆分镜头，随后生成、合成并在导出前确认参数。
你是 TikTok 创作剪辑师...
```

**优势**：
- 创作者直接可读可写（MD + YAML）
- AI 可自行修改优化（演化能力基础）
- 社区分发门槛低（单文件分享）
- 合规审计天然支持（skillSha 证据链）

详见 [agent-unified-workflow.md §5](./agent-unified-workflow.md#5-l1-能力层skill-为核心--扁平工具池)。

## 9. 四档感知策略

### 9.1 真正的隐私边界

**问题澄清**：真正的隐私边界不是"Agent 能不能看"，而是 **"数据能否离开本地 + 能否不被用户看见 + 能否被挪作他用"**。

| 维度 | 默认可做 | 默认不可做 |
|-----|---------|-----------|
| **读本地文件** | ✅ 项目目录内 | ❌ 项目目录外 |
| **记录操作** | ✅ 本地 JSONL | ❌ 上传云端 |
| **上下文注入 LLM** | ✅ 本次会话 | ❌ 跨用户共享 |
| **生成画像** | ⚠️ 用户可见时 | ❌ 黑箱累积 |
| **用于训练** | ❌ 始终需同意 | ❌ 匿名也不行 |

### 9.2 四档分层

| 档位 | 内容 | 默认状态 | 理由 |
|------|------|---------|------|
| **L1 读项目文件** | Agent 工作前提 | ✅ 开（透明可见）| Agent 运行即需要 |
| **L2 记录操作历史** | 本地 JSONL 时间线 | ✅ 开（用户受益）| 零成本纯本地 |
| **L3 当前会话意图** | 单次对话内意图理解 | ✅ 开（被动响应）| Agent 工作必需 |
| **L4 长期画像推理** | 跨会话美学累积 + 主动建议 | ❌ 显式开启 | 用户真正担心的 |

### 9.3 核心原则

- **浅层透明观察默认开**（Agent 本就需要）
- **深层主动推理默认关**（用户真正担心的）
- **任何层都可一键隐身**
- 所有数据留在 `.neko/` 用户可见可删

### 9.4 关键 UX 设计原则

1. **Agent 的"视野"应可见** —— 侧边栏显示当前能看到什么，"透明观察"而非"隐蔽观察"
2. **主动推理要留痕** —— L4 开启时所有建议标注来源，可解释性是信任基础
3. **隐身模式一键切换** —— 临时关闭所有记录，给"探索性创作"留空间
4. **数据主权** —— 所有记录用户可见可删可导出，"数据不是 Agent 的，是用户的"

## 10. EditOperation 现状与升维

### 10.1 现状评估

**现有机制**（基础设施已有）：
- neko-cut Timeline 编辑有 Command/Undo 栈
- neko-canvas 节点编辑有状态快照
- neko-model 骨骼操作走 bevy_ecs 事件
- neko-sketch 笔触有独立 stroke 事件

**问题**：
- **各子包独立实现**，schema 不统一
- **服务于 undo/redo**，不服务于"意图推断"
- **粒度错配**：undo 需要原子操作，意图推断需要语义操作
- **生命周期错配**：undo 栈关闭就丢，意图需跨会话累积

### 10.2 升维路径

**不是"从零建传感器"，而是"在现有 Command 栈旁加语义分流管道"**：

```
现有：用户操作 → Command 栈（undo/redo）

升维：用户操作 → Command 栈（undo/redo）
                ↓ 语义分流
                OperationEvent（统一 schema）
                ↓
                .neko/operations/*.jsonl（本地时间线）
                ↓
                语义聚合层（原子 → 意图）
                ↓
                Agent 意图理解
```

**真实工作量**：成本比预想低，但**不能直接复用 undo 栈**。

## 11. AIGC 自动补全的多模态挑战

### 11.1 与代码补全的对比

**Copilot 补全为什么简单**：
- 代码是一维文本流
- 上下文就是"前 N 行"
- 延续预测在模型能力内
- 延迟容忍度高（几百毫秒 OK）

**创作工具补全的复杂性**：

| 场景 | 补全目标 | 技术难题 |
|------|---------|---------|
| Timeline 下一剪辑点 | 时间点 + 镜头选择 | 需理解节奏/视频内容/音频波形 |
| Canvas 下一节点 | 节点类型 + 连线 + 参数 | 需理解图的语义/数据流意图 |
| Sketch 笔触延续 | 路径 + 压感 + 颜色 | 需理解形状意图/风格一致性 |
| Model 骨骼姿态 | 下一关键帧 | 需理解运动意图/物理合理性 |

### 11.2 核心挑战

1. **延迟预算紧**（创作者手感要求 < 100ms）—— 主流大模型跑不动
2. **多模态输入复杂**（视频/音频/几何/向量图）—— 需专用小模型
3. **评估标准模糊**（代码对错客观，创作好坏主观）—— 接受率难优化
4. **训练数据稀缺**（代码有 GitHub，创作专业数据少）—— 起步门槛高

### 11.3 现实判断

- **L2 短期不是"默认开启"的成熟功能**
- 需要**按子包逐个攻坚**（先挑技术最容易的，如 Timeline 剪辑点预测）
- 早期可能**长时间处于实验功能**
- 用"**建议而非补全**"降低门槛（推一组选项让用户选，而非内联预测）

## 14. 设计反模式（禁止）

### 架构反模式

- ❌ Agent 与创作工具各自为战（应通过 CapabilityProvider 统一）
- ❌ 单聊天框作为唯一入口（应升级为意图画布）
- ❌ 工具操作只做 undo 不做意图捕获（失去最大传感器价值）

### 意图反模式

- ❌ 强制文本描述（多模态阻抗失配）
- ❌ 意图层锁死技术层（失去专业控制）
- ❌ 技术层为 Agent 牺牲（破坏独立操作体验）

### 感知反模式

- ❌ 静默深度观察（Cursor/Copilot 踩雷方向）
- ❌ 数据黑箱累积（用户应可见可编辑）
- ❌ 感知能力不透明（Agent 视野必须可见）

### Skill 反模式

- ❌ Skill 用 DSL 而非 MD（失去创作者可读可写）
- ❌ AI 不能修改 Skill（失去演化能力）
- ❌ market 碎片化分发（用户心智负担）

---

## 15. 三句话概括

1. **意图驱动是未来，但必须多模态** —— 文本只是入口之一，创作工具本身就是最强意图传感器
2. **Agent 不是工具替代者，是意图编译器** —— 把用户 What 翻译为工具 How，同时观察工具操作反向更新意图理解
3. **护城河在深度集成** —— Cursor 赢在工具链深耕、Midjourney 赢在创作专注、neko-suite 赢点在**"创作工具生态 × Agent 基础设施"的正交能力矩阵**

---

## 16. 战略定位

### 16.1 应押注的战略三角

```
    创作工具生态（cut/canvas/model/sketch/puppet/story）
             /                              \
            /                                \
           /                                  \
    Agent 基础设施                          Rust 引擎
    （Skills/SDD/Auto Heal）              （FFmpeg/wgpu/ONNX）
              \                          /
               \                        /
                \                      /
              意图画布 + 双向编译 + 多模态捕获
              （Agent × 创作工具的化学反应点）
```

### 16.2 赢的方式

**不是在任何单点超越对手**，而是在**三角交汇点**做到没人能做到的事——这是 Runway（无工具生态）、Cursor（无创作领域）、Adobe（Agent 能力弱）、ChatGPT（无垂直工具）都无法复制的组合。

### 16.3 时间窗口判断

| 时间窗口 | 意图驱动定位 |
|---------|-------------|
| **2026-2028** | 新用户默认入口，老用户可选路径 |
| **2028-2030** | 主流创作工具默认交互，技术面板成"高级选项" |
| **2030+** | 类比今天的"代码编辑器 vs IDE"——意图层就是新的 GUI |

## 17. 终极判断

**把每个创作子包都变成 Agent 的感官，把 Agent 变成意图的编译器，把意图画布变成创作的新语言**——这就是意图驱动创作 IDE + Agent 的完整设计蓝图。
