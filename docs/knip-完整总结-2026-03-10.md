## 🎓 经验总结

### 关键洞察

1. **区分问题优先级**: Unused Files/Dependencies/Duplicate Exports 是高优先级问题，Unused Exports 是低优先级
2. **理解工具限制**: knip 无法检测 HTML → TS 的依赖关系，需要手动配置 entry
3. **合理使用 ignore**: 对于待实现功能，使用 ignore 而非删除代码
4. **渐进式改进**: 不必一次性解决所有问题，优先处理高价值问题

### 最佳实践

**导出风格**:
```typescript
// ✅ 推荐：命名导出
export function MyComponent() { ... }
export class MyService { ... }

// ❌ 避免：默认导出（除配置文件外）
export default MyComponent;
```

**依赖管理**:
1. 依赖声明在使用它的最近包中
2. 父包不声明子包的依赖
3. peer dependencies 显式声明

**Knip 配置**:
1. 精确的 entry 声明（webview 入口）
2. 合理的 ignore 规则（待实现功能、barrel exports）
3. ignoreDependencies 处理间接依赖
